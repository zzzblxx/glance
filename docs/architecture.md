# 项目结构与扩展

Glance 区分四个概念：数据来源、设备型号、连接方式、页面布局。
当前实际支持 OpenAI＋E1003＋USB 串口；目录结构允许扩展，不代表已经支持其他来源或设备。

## 数据来源

`internal/providers/provider.go` 定义采集接口，提供来源身份、额度、活动摘要和资源关闭操作。
`internal/providers/openai/` 是当前适配器，内部通过 `codex/` 调用 Codex app-server、读取本机活动。
主服务的轮询、缓存、任务 ID 加盐和错误状态处理不再直接依赖 Codex 客户端类型。
通过 `NewWithProvider` 可注入其他实现；目前正常启动只注册 OpenAI。

服务商 ID 为 `openai`，界面名称为 `ChatGPT`，读取接口为 Codex，三者不能互相替代。
额度保留真实 bucket 标识，展示名不表示所有 ChatGPT 功能共享一个余额。
已有便签中的 Codex 文案属于便签内容，不因标题改名自动覆盖。

统一模型在 `internal/model/`：窗口包含名称、时长、额度和重置时间，不要求一定是 5 小时／7 天。
重置能力 `false` 表示不支持；剩余 0 次表示支持但已用完；未知与二者分开。
旧缓存没有能力字段时保留原有行为，没有时长时兼容既有窗口名称。
`internal/protocol/` 当前仍含 5 小时／7 天首页的数据投影，其他窗口保留到详情页；
这不是声称任意来源都已具备合适的首页布局。

## 设备与传输

`internal/devices/e1003/profile.go` 定义型号、串口速率、协议及绘图兼容版本、分辨率、灰度和页数上限。
`internal/transport/serial/` 接收设备参数，验证选定型号和绘图版本，再发送结构化快照；
不自动扫描配对、不将任意插入设备视为可信设备，也不传送图片。
当前串口快照协议共用；不兼容该协议的新设备应提供单独适配，而非伪装成 E1003。

`firmware/e1003/` 独立包含 PlatformIO 项目、硬件初始化、按键、刷新和该屏幕的布局。
`native/e1003/` 与固件编译同一绘图头文件，用于 Mac 预览与像素测试。
`internal/devices/e1003/nativeview/` 调用这个助手。
现有 `internal/render/` 保留公共帧类型及旧传输兼容绘图，不是任意尺寸屏幕的通用布局引擎。

## 素材与产物

- `assets/fonts/`：字库原文件、转换后字库、来源和许可证。
- `assets/banners/`：四张横幅原图及来源说明。
- `firmware/shared/`：由横幅生成器产生、供固件和预览实际共用的素材。
- `firmware/e1003/generated/`：构建时暂存字库，稳定嵌入符号；不提交 Git。
- `artifacts/e1003/`：可刷写镜像与校验文件。
- `docs/assets/`：固定示例数据生成的预览，不包含真实账户信息。

## 增加支持时的边界

新增来源：实现 provider 接口，明确字段和能力，将认证与来源私有逻辑保留在对应目录，
注册配置并添加测试。若没有可靠的活动接口，不得把“未知”当作“没有任务”。
新增设备：增加型号参数、固件、布局／预览适配、构建与刷写流程，并做实机验证。
不能仅改变型号字符串就声称支持新屏幕。
设备类型与传输类型分别选择，不能根据 `usb` 就推断它是 E1003。

当前 `provider`、`device_model` 的默认值兼容旧配置。未实现的值明确拒绝。
本轮不加入虚假的 Anthropic 实现，不加入插件加载系统，也不改动现有用户配对和便签。
